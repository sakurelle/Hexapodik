Работай с текущим `RP2040RobotController`.

Сейчас робот работает, но максимальная скорость искусственно сильно ограничена. Нужно выставить максимально возможный профиль скорости для текущей геометрии и gait, исправить неправильное вычисление частоты шага и добавить диагностику скорости.

Не менять contact logic, PIO/DMA, IK/FK, ServoConfig и UART architecture без необходимости.

## 1. Текущая проблема

Сейчас в `robot_config.h`:

```cpp
kMaxVxMmS = 80
kMaxVyMmS = 0
kMaxYawRadS = 0.45

kMaxVxAccelMmS2 = 200
kMaxVyAccelMmS2 = 200
kMaxYawAccelRadS2 = 1.5

kMinCycleHz = 0.6
kMaxCycleHz = 1.5
```

Кроме того, в `gait_generator.cpp` частота gait вычисляется неправильно:

```cpp
const float command_level =
    std::clamp(commandMagnitude(command) / 125.0f, 0.0f, 1.0f);
```

При `vx=80` это даёт только:

```text
80 / 125 = 0.64
```

поэтому чистый full-forward даже не достигает `kMaxCycleHz`.

Эту схему удалить.

## 2. Максимальный профиль

Для текущей геометрии:

```text
Coxa = 44 mm
Femur = 80 mm
Tibia = 125.24 mm

joint safety margin = 5°
swing height = 30 mm
stance duty = 0.65
```

расчётный безопасный workspace с уже существующим 5° margin позволяет примерно:

```text
forward half-stride ≈ 91 mm
```

При максимальной частоте:

```cpp
constexpr float kMaxCycleHz = 1.575f;
```

получается:

```text
max Vx ≈ 440 mm/s
```

Установить:

```cpp
constexpr float kMaxVxMmS = 440.0f;
constexpr float kMaxVyMmS = 355.0f;
constexpr float kMaxYawRadS = 3.0f;
```

`Vy` сейчас RC не использует, но он нужен для будущего ROS2 `/cmd_vel`.

## 3. Почему max cycle = 1.575 Hz

Текущий swing занимает:

```text
1 - kStanceDuty = 0.35 cycle
```

Descend занимает:

```text
0.82 ... 1.00 swing
= 18% swing
```

Итого:

```text
0.35 * 0.18 = 0.063 полного цикла
```

Servo targets обновляются 50 Hz = каждые 20 ms.

Требование:

```text
Descend >= 2 servo frames = 40 ms
```

Отсюда:

```text
0.063 / cycleHz >= 0.040
cycleHz <= 1.575 Hz
```

Поэтому для текущей формы trajectory:

```cpp
kMaxCycleHz = 1.575f;
```

Не увеличивать выше без изменения swing trajectory или servo output update frequency.

## 4. Acceleration

Сделать разгон достаточно быстрым, чтобы max command достигался примерно за половину цикла на максимальной скорости.

При:

```text
1 / 1.575 ≈ 0.635 s
half-cycle ≈ 0.317 s
```

установить:

```cpp
constexpr float kMaxVxAccelMmS2 = 1400.0f;
constexpr float kMaxVyAccelMmS2 = 1150.0f;
constexpr float kMaxYawAccelRadS2 = 10.0f;
```

Это должно позволять почти полностью изменить команду за ~half-cycle.

Slew limiter оставить.

## 5. Исправить command_level

Не использовать:

```cpp
commandMagnitude(command) / 125
```

Использовать нормализацию каждой оси относительно её реального максимума:

```cpp
const float vx_level =
    std::fabs(command.vx_mm_s) / kMaxVxMmS;

const float vy_level =
    kMaxVyMmS > 0.0f
        ? std::fabs(command.vy_mm_s) / kMaxVyMmS
        : 0.0f;

const float yaw_level =
    std::fabs(command.yaw_rad_s) / kMaxYawRadS;

const float command_level = std::clamp(
    std::max({vx_level, vy_level, yaw_level}),
    0.0f,
    1.0f
);
```

Таким образом:

```text
100% forward -> kMaxCycleHz
100% strafe  -> kMaxCycleHz
100% yaw     -> kMaxCycleHz
```

Не должно требоваться одновременно forward+yaw для достижения максимальной частоты.

## 6. Cycle frequency

Оставить интерполяцию:

```cpp
cycle_hz =
    kMinCycleHz +
    (kMaxCycleHz - kMinCycleHz) * command_level;
```

`kMinCycleHz` пока оставить:

```cpp
constexpr float kMinCycleHz = 0.6f;
```

То есть малые команды остаются управляемыми, а full stick сразу получает максимум.

## 7. Проверить stride

Для прямого движения полный nominal stride можно считать:

```cpp
stride_mm =
    std::fabs(vx_mm_s) *
    kStanceDuty /
    cycle_hz;
```

При максимуме должно получаться примерно:

```text
440 * 0.65 / 1.575
≈ 181.6 mm
```

Half-stride:

```text
≈ 90.8 mm
```

Это почти текущий геометрический максимум примерно 91 мм.

Не увеличивать `Vx` выше 440 мм/с при этой частоте и текущем workspace.

## 8. Workspace scaling оставить

Существующий:

```text
findWorkspaceScale()
```

обязательно сохранить.

Для смешанной команды:

```text
forward + yaw
forward + strafe
strafe + yaw
```

индивидуальные максимумы могут одновременно быть недостижимы.

В этом случае текущий workspace scaler должен пропорционально уменьшить весь body twist:

```text
vx
vy
yaw
```

одним коэффициентом.

Не clamp'ить отдельные оси независимо после генерации gait.

## 9. Проверить max envelope host-side

Не просто захардкодить числа.

Добавить host-side тест/utility, который численно проверяет текущий speed envelope.

Для заданного `cycle_hz = kMaxCycleHz`:

### Pure forward

Увеличивать `vx` до момента, когда trajectory перестаёт проходить:

```text
IK
joint limits
5° safety margin
singularity
swing height
```

Проверять полный stance/swing trajectory всех 6 ног, а не только landing point.

Ожидаемый предел:

```text
~440 mm/s
```

### Pure strafe

Аналогично:

```text
~355 mm/s
```

### Pure yaw

Аналогично:

```text
~3.0 rad/s
```

Допуск на численную дискретизацию разумный.

Если реальный расчёт по существующему коду даст немного меньший предел — использовать фактически вычисленный предел, округлённый немного вниз.

Не использовать мои значения слепо, если текущая реализация геометрии отличается.

## 10. Servo physical speed

В проекте пока нет точной модели физической скорости сервоприводов.

Поэтому НЕ вводить выдуманный servo-speed limiter.

Но добавить diagnostics, позволяющую измерить требования к сервам.

Каждый control tick вычислять для каждой сервы:

```cpp
joint_velocity_rad_s =
    abs(q_new - q_previous) / dt;
```

Хранить:

```text
max_requested_joint_velocity_rad_s
max_requested_joint_velocity_deg_s
```

за последний diagnostic interval.

Не ограничивать по этому значению пока.

Нужно увидеть реальные требования на физическом роботе, после чего предел можно будет выставить по datasheet/измерению серв.
