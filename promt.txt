# Исправить рабочую стойку и убрать рывки tripod gait

Работай с текущей локальной версией `RP2040RobotController`.

Проект был проанализирован вручную. В текущей реализации найдена конкретная проблема последовательности RC tripod gait, из-за которой робот ходит рывками.

Не переписывай проект с нуля.

Не менять:

* PIO servo driver;
* DMA;
* частоту 50 Гц;
* GPIO серв;
* GP0/GP1 RC input;
* ServoConfig;
* существующую зеркальную калибровку левой/правой стороны;
* `center_us=1500`;
* RC input и arming, если для этой задачи это не требуется.

---

## 1. Новая рабочая стойка

Физически установлено следующее.

Для ЛЕВОЙ стороны в рабочем положении требуется:

```text
Coxa  = 1500 us
Femur = 1600 us
Tibia = 1500 us
```

Для ПРАВОЙ стороны должна быть зеркальная команда:

```text
Coxa  = 1500 us
Femur = 1400 us
Tibia = 1500 us
```

Не реализовывать это прямыми pulse override.

Текущая временная ServoConfig уже зеркальная:

```text
RIGHT:
-45° = 2000
  0° = 1500
+45° = 1000

LEFT:
-45° = 1000
  0° = 1500
+45° = 2000
```

Следовательно общий логический угол:

```text
Femur = +9°
```

даёт приблизительно:

```text
LEFT  Femur = 1600 us
RIGHT Femur = 1400 us
```

Поэтому изменить:

```text
config/robot_params.txt
```

на:

```text
STAND_COXA_DEG=0
STAND_FEMUR_DEG=9
STAND_TIBIA_DEG=0
```

Это должна быть единая логическая `STAND_POSE` для всех шести ног.

Не менять `center_us=1500`.

`ZERO_POSE` также оставить:

```text
0°, 0°, 0°
```

То есть:

* ZERO_POSE = механический ноль серв;
* STAND_POSE = рабочая нейтраль робота.

# 3. Найденная ошибка текущего RC gait

В текущем:

```text
src/robot/gait_controller.cpp
```

есть логическая проблема.

Сейчас:

```cpp
drive_cycle_start_pose()
```

всегда возвращает:

```text
Tripod A Coxa = backward
Tripod B Coxa = forward
```

После этого `drive_prelift_pose()` всегда строится именно от этой позы.

Но после `A_TRANSFER/A_LOWER` реальная корректная поза уже обратная:

```text
Tripod A = forward
Tripod B = backward
```

После этого начинается `B_PRELIFT`, а `drive_prelift_pose(TRIPOD_B)` снова задаёт:

```text
A = backward
B = forward
```

То есть ВСЕ Coxa резко начинают возвращаться назад уже во время PRELIFT.

Далее `drive_lift_pose(TRIPOD_B)` содержит специальный hack:

```cpp
if (gait::leg_in_tripod(servo::Leg::FL, tripod)) {
    set_drive_tripod_coxa(... TRIPOD_A, true ...);
    set_drive_tripod_coxa(... TRIPOD_B, false ...);
}
```

и снова переворачивает положение Coxa:

```text
A = forward
B = backward
```

После этого `B_TRANSFER` опять переводит их:

```text
A = backward
B = forward
```

Таким образом при полушаге B Coxa двигаются:

```text
A_LOWER
A forward / B backward

↓

B_PRELIFT
A backward / B forward

↓

B_LIFT
A forward / B backward

↓

B_TRANSFER
A backward / B forward
```

Это неверно.

Coxa должны менять положение только во время TRANSFER.

Исправить архитектуру pose generation.

# 4. Правильная последовательность Tripod A

Перед подъёмом A:

```text
Tripod A Coxa = BACKWARD
Tripod B Coxa = FORWARD
```

### A_PRELIFT

Coxa НЕ двигать:

```text
A = BACKWARD
B = FORWARD
```

Меняется только Femur/Tibia Tripod A.

### A_LIFT

Coxa всё ещё:

```text
A = BACKWARD
B = FORWARD
```

Меняются только Femur/Tibia A до полной lift pose.

### A_TRANSFER

Только здесь выполнить движение Coxa:

```text
A: BACKWARD -> FORWARD
B: FORWARD  -> BACKWARD
```

A находится в воздухе.

B стоит на земле и двигает корпус.

### A_LOWER

Coxa оставить:

```text
A = FORWARD
B = BACKWARD
```

Менять только Femur/Tibia A.

После A_LOWER итог:

```text
A = FORWARD
B = BACKWARD
```

---

# 5. Правильная последовательность Tripod B

B должен начинаться непосредственно из конечного положения A.

### B_PRELIFT

Coxa НЕ двигать:

```text
A = FORWARD
B = BACKWARD
```

Поднять только Femur B на prelift.

### B_LIFT

Coxa всё ещё:

```text
A = FORWARD
B = BACKWARD
```

Полностью поднять B.

### B_TRANSFER

Только теперь:

```text
A: FORWARD  -> BACKWARD
B: BACKWARD -> FORWARD
```

### B_LOWER

Coxa оставить:

```text
A = BACKWARD
B = FORWARD
```

Опустить только B.

После B_LOWER состояние автоматически совпадает с началом следующего:

```text
A_PRELIFT
```

Никакого дополнительного reposition Coxa между циклами быть не должно.

# 6. Переписать pose helpers без специальных hack

Убрать текущую специальную проверку:

```cpp
if (gait::leg_in_tripod(servo::Leg::FL, tripod))
```

из `drive_lift_pose()`.

Она является признаком неправильной модели фаз.

Сделать понятные helper-функции.

Например:

```cpp
RobotPose drive_before_transfer_pose(
    const std::array<servo::Leg, 3>& swing_tripod,
    const DriveMix& mix,
    float swing_deg
);
```

Поведение:

Для Tripod A:

```text
A backward
B forward
```

Для Tripod B:

```text
A forward
B backward
```

Затем:

```cpp
drive_prelift_pose(...)
```

строится из `drive_before_transfer_pose()` и меняет ТОЛЬКО Femur/Tibia.

```cpp
drive_lift_pose(...)
```

также строится из `drive_before_transfer_pose()` и меняет ТОЛЬКО Femur/Tibia.

Отдельно:

```cpp
drive_after_transfer_pose(...)
```

возвращает положение Coxa после переноса.

Для A:

```text
A forward
B backward
```

Для B:

```text
A backward
B forward
```

`drive_transfer_pose()`:

* использует `drive_after_transfer_pose`;
* оставляет swing tripod поднятым.

`drive_lower_pose()`:

* использует то же `drive_after_transfer_pose`;
* возвращает Femur/Tibia swing tripod в STAND;
* НЕ меняет Coxa.

# 7. Проверить непрерывность всех фаз

Добавить host tests.

Для каждого перехода проверить Coxa targets.

### A_PRELIFT -> A_LIFT

Coxa не изменились.

### A_LIFT -> A_TRANSFER

Coxa меняются один раз.

### A_TRANSFER -> A_LOWER

Coxa не изменились.

### A_LOWER -> B_PRELIFT

Coxa должны быть АБСОЛЮТНО одинаковыми.

Это особенно важный regression test.

### B_PRELIFT -> B_LIFT

Coxa не изменились.

### B_LIFT -> B_TRANSFER

Coxa меняются один раз.

### B_TRANSFER -> B_LOWER

Coxa не изменились.

### B_LOWER -> next A_PRELIFT

Coxa должны быть АБСОЛЮТНО одинаковыми.

До исправления как минимум переход:

```text
A_LOWER -> B_PRELIFT
```

должен проваливать тест.

# 8. Вторая причина рывков: текущий MotionController

Текущий:

```cpp
MotionController::set_target_timed()
```

фактически НЕ выполняет синхронную timed interpolation.

Сейчас код находит:

```cpp
max_delta
```

и превращает duration в одну общую скорость:

```cpp
speed = max_delta / seconds
```

Далее `update()` для каждого сустава делает:

```cpp
current += +/- step
```

с одним и тем же `step`.

Из-за этого:

1. сустав с максимальным delta движется всё время;
2. суставы с меньшим delta приходят в target раньше;
3. они резко останавливаются посреди фазы;
4. на переходе между фазами скорость мгновенно меняется;
5. ускорение/торможение отсутствует.

Это даёт визуально дёрганое движение даже после исправления GaitController.

Исправить timed motion.

---

# 9. Сделать настоящую интерполяцию позы по времени

Для `set_target_timed()` хранить:

```cpp
RobotPose start_pose_;
RobotPose target_pose_;

uint32_t duration_us_;
uint32_t elapsed_us_;
```

или эквивалент.

При:

```cpp
set_target_timed(target, duration_ms)
```

запомнить:

```text
start_pose = current_pose
target_pose = target
elapsed = 0
duration = duration_ms
```

Во время `update(elapsed_us)`:

```cpp
elapsed += elapsed_us;

t = clamp(elapsed / duration, 0...1)
```

ВСЕ суставы должны интерполироваться от своего start к своему target через один и тот же `t`.

То есть:

```cpp
angle =
    start_angle +
    (target_angle - start_angle) * interpolation(t);
```

Тогда все 18 суставов закончат фазу одновременно.

---

# 10. Добавить плавное acceleration/deceleration

Не использовать обычный linear `t` для gait.

Использовать минимум cubic smoothstep:

```cpp
smooth = t * t * (3.0f - 2.0f * t);
```

Ещё лучше smootherstep:

```cpp
smooth =
    t * t * t *
    (t * (t * 6.0f - 15.0f) + 10.0f);
```

Предпочтительно использовать `smootherstep`.

Это даст:

* нулевую скорость в начале фазы;
* плавное ускорение;
* плавное торможение;
* нулевую скорость в конце.

Добавить enum:

```cpp
enum class MotionInterpolation {
    Linear,
    SmoothStep,
    SmootherStep
};
```

Для gait использовать:

```text
SmootherStep
```

Для сервисного управления отдельной сервой можно сохранить Linear, если это полезно.

---

# 11. Не создавать рывок при начале новой фазы

При каждом:

```cpp
set_target_timed()
```

start_pose должен браться из ФАКТИЧЕСКОЙ:

```cpp
current_
```

а не из предыдущей `target_`.

Это важно, если новая команда поступила раньше полного окончания предыдущего движения.

# 12. set_target обычной скоростью сохранить

Не ломать существующий:

```cpp
set_target(pose, speed_deg_per_sec)
```

если он нужен UART/service functionality.

Можно иметь два режима MotionController:

```text
SpeedLimited
TimedSmooth
```

Но все gait phases через:

```cpp
set_target_timed()
```

должны использовать новую синхронную плавную интерполяцию.

# 13. Исправить длительности фаз после smoothing

Текущие RC timings формируются:

```cpp
rc_prelift_ms_ = cycle_ms / 10
rc_lift_ms_ = cycle_ms / 10
rc_transfer_ms_ = cycle_ms / 4
rc_lower_ms_ = cycle_ms / 8
```

Пока оставить общую зависимость скорости от стика.

Но после перехода на smootherstep установить разумные минимумы:

```text
PRELIFT minimum = 80 ms
LIFT minimum    = 100 ms
TRANSFER minimum= 160 ms
LOWER minimum   = 120 ms
```

Не использовать текущие минимумы 40/40/80/40 ms при быстром gait.

Для MG996R и текущей механики это слишком резкие фазовые изменения для первого теста.

Оставить параметры конфигурируемыми.

Добавить в `robot_params.txt`:

```text
GAIT_PRELIFT_MIN_MS=80
GAIT_LIFT_MIN_MS=100
GAIT_TRANSFER_MIN_MS=160
GAIT_LOWER_MIN_MS=120
```

получится:


```text

```

Это остаётся внутри ±45°.

Не менять эти значения автоматически в этой задаче.

# 15. Подъём ноги должен происходить до Coxa transfer

Очень важно проверить последовательность визуально и тестами:

```text
STAND
↓
PRELIFT Femur
↓
FULL LIFT Femur + Tibia
↓
COXA TRANSFER
↓
LOWER
```

При PRELIFT/LIFT Coxa конкретного полушага не должны двигаться.

Это соответствует требуемой механике:

сначала немного оторвать tibia от пола,
затем поднять ногу,
и только после этого переносить её.

# 16. Не использовать новые targets из RC внутри текущей фазы

Сейчас `drive_command_` и `drive_mix_` обновляются каждый main loop.

Но текущий MotionController target меняется только при следующем `begin_phase`.

Сохранить этот принцип.

Не менять pose target посреди PRELIFT/LIFT/TRANSFER каждые несколько миллисекунд из-за джиттера стика.

Новые:

```text
speed
direction
turn
swing
```

должны применяться только при начале следующей gait phase.

Это уменьшает рывки от RC input.

При необходимости хранить:

```cpp
pending_drive_command_
```

и:

```cpp
active_phase_drive_command_
```

На начале каждой новой фазы делать snapshot pending command.

Не перенацеливать MotionController непрерывно внутри одной фазы.

```text

```

и:

```text

```

Ни один сустав не должен завершить движение раньше остальных.
