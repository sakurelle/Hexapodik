RP2040RobotController

Нужно добавить первый демонстрационный алгоритм движения шестиногого
робота.

Текущая прошивка уже корректно:

- центрирует 18 серв;
- переходит в STAND_POSE;
- удерживает стойку;
- зеркально управляет левой и правой сторонами;
- непрерывно формирует сигналы через PIO.

Эту работающую часть не ломать.

Не менять:

- PIO-драйвер;
- DMA;
- частоту серв 50 Гц;
- распиновку;
- ServoConfig;
- калибровки;
- UART GP0/GP1;
- StartupController без необходимости.

Текущая STAND_POSE:

Coxa  = 0°
Femur = -15°
Tibia = +20°

Нужно добавить отдельный верхнеуровневый модуль GaitController.

Создать примерно:

include/robot/gait_controller.hpp
include/robot/gait_config.hpp
src/robot/gait_controller.cpp

GaitController должен работать поверх существующего MotionController.

Он не должен:

- работать напрямую с PIO;
- работать с pulse_us;
- обращаться к GPIO;
- использовать sleep_ms/sleep_us;
- блокировать UART;
- блокировать основной цикл.

Все движения должны выполняться через существующий MotionController.

--------------------------------------------------
ЭТАП 1 — MARCH IN PLACE
--------------------------------------------------

Сначала реализовать безопасную демонстрацию подъёма ног без движения Coxa.

Обычная нога:

Coxa  = 0°
Femur = -15°
Tibia = +20°

Начальная тестовая поднятая нога:

Coxa  = 0°
Femur = -7°
Tibia = +12°

То есть относительно STAND_POSE:

Femur += 8°
Tibia -= 8°

Эти значения вынести в gait_config.hpp:

constexpr float GAIT_LIFT_FEMUR_DELTA_DEG = 8.0f;
constexpr float GAIT_LIFT_TIBIA_DELTA_DEG = -8.0f;

Не размножать числа по коду.

Последовательность MARCH:

1. Все ноги STAND.
2. Поднять Tripod A.
3. Удержать.
4. Опустить Tripod A.
5. Поднять Tripod B.
6. Удержать.
7. Опустить Tripod B.
8. Вернуться в STAND.

Сделать 2 полных цикла.

Начальные времена:

LIFT_TIME_MS = 300
HOLD_TIME_MS = 200
LOWER_TIME_MS = 300

Всё должно быть неблокирующим state machine.

После завершения MARCH робот остаётся в STAND_POSE.

--------------------------------------------------
ЭТАП 2 — DEMO TRIPOD WALK
--------------------------------------------------

Добавить демонстрационную открытую tripod gait.

Это пока НЕ обратная кинематика.

Использовать движение непосредственно в углах суставов.

Начальная амплитуда Coxa:

constexpr float GAIT_COXA_SWING_DEG = 8.0f;

Добавить таблицу направления движения Coxa для каждой ноги:

std::array<float, 6> COXA_FORWARD_SIGN

По умолчанию:

FR = +1
MR = +1
RR = +1
RL = +1
ML = +1
FL = +1

Это не ServoConfig inversion.

Это только преобразование глобального направления движения робота
в локальное направление движения Coxa конкретной ноги.

В дальнейшем эту таблицу можно будет изменить после механического теста.

Создать функции примерно:

float forwardCoxa(Leg leg);
float backwardCoxa(Leg leg);

где:

forward  = +GAIT_COXA_SWING_DEG * sign
backward = -GAIT_COXA_SWING_DEG * sign

--------------------------------------------------
ЦИКЛ ХОДЬБЫ
--------------------------------------------------

Перед началом движения робот находится в STAND_POSE.

Добавить PREPARE фазу:

Tripod A:
Coxa = backward

Tripod B:
Coxa = forward

Все Femur/Tibia остаются в STAND.

Переход выполнять плавно примерно за 500 мс.

Далее один цикл:

A_LIFT

Tripod A:
Femur = STAND + 8°
Tibia = STAND - 8°

Tripod B:
остаётся на земле.

---

A_TRANSFER

Tripod A поднят и перемещается:

Coxa backward -> forward

Tripod B находится на земле и одновременно:

Coxa forward -> backward

Это движение должно перемещать корпус вперёд.

---

A_LOWER

Tripod A:
Femur -> STAND
Tibia -> STAND

Coxa остаётся forward.

---

B_LIFT

Tripod B поднять:

Femur = STAND + 8°
Tibia = STAND - 8°

---

B_TRANSFER

Tripod B поднят:

Coxa backward -> forward

Tripod A стоит на земле:

Coxa forward -> backward

---

B_LOWER

Tripod B вернуть на землю.

После этого состояние совпадает с началом следующего цикла.

В демонстрационном режиме выполнить только:

3 полных цикла.

После третьего цикла:

1. убедиться, что все шесть ног стоят на земле;
2. плавно вернуть все Coxa в 0°;
3. вернуть точную STAND_POSE;
4. остановить gait;
5. продолжать удерживать STAND_POSE.

--------------------------------------------------
БЕЗОПАСНОСТЬ
--------------------------------------------------

Все генерируемые углы обязательно проверить через существующие ограничения
ServoConfig.

Никакой угол не должен выходить за:

-45° ... +45°

при текущей временной калибровке.

При ошибке gait должен:

1. остановиться;
2. плавно вернуться в STAND_POSE, если это безопасно;
3. вывести диагностическое сообщение.

DISABLE ALL должен иметь абсолютный приоритет.

Если во время gait приходит DISABLE ALL:

- GaitController немедленно прекращает работу;
- существующая логика отключения серв работает как раньше.

ALL CENTER и STAND также должны отменять активный gait.

--------------------------------------------------
АРХИТЕКТУРА
--------------------------------------------------

main.cpp не должен содержать огромный switch gait-состояний.

В main должно быть примерно:

g_gait.update(...)

MotionController остаётся ответственным только за интерполяцию углов.

GaitController отвечает за:

- последовательность фаз;
- tripod groups;
- формирование RobotPose;
- количество циклов.

PIO Servo Driver отвечает только за импульсы.

Servo calibration отвечает только за angle -> pulse.

Не смешивать эти уровни.
