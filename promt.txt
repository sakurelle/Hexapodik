Нужно создать в корне репозитория новый независимый проект прошивки для Waveshare RP2040-Zero. Существующий проект `ServoTester` не удалять, не переносить и не переделывать.

Название нового каталога:

`RP2040RobotController`

## Цель текущего этапа

Создать первую рабочую прошивку контроллера 18 сервоприводов шестиногого робота.

На этом этапе не нужно реализовывать ходьбу, обратную кинематику или генератор походки. Прошивка должна:

1. Управлять всеми 18 сервоприводами через PIO.
2. После запуска безопасно перевести все сервоприводы сначала в центр.
3. Затем плавно перевести робота в начальную стойку.
4. Продолжать формировать импульсы, чтобы робот удерживал стойку.
5. Одновременно продолжать принимать команды по UART без блокировок.
6. Иметь архитектуру, пригодную для дальнейшего добавления движения и походок.

Используй C++ и официальный Raspberry Pi Pico C/C++ SDK с CMake.

Не используй Arduino Framework.

Не используй обычный аппаратный PWM для управления всеми 18 сервами.

Не создавай отдельную PIO state machine для каждой сервы.

## Ориентация робота

Распиновка задана для следующего положения:

* на робота смотрят сверху;
* задняя часть робота направлена к наблюдателю;
* правая сторона робота находится слева на виде сверху;
* передняя часть направлена от наблюдателя.

Использовать следующие обозначения:

* `FR` — Front Right;
* `MR` — Middle Right;
* `RR` — Rear Right;
* `RL` — Rear Left;
* `ML` — Middle Left;
* `FL` — Front Left.

## Строго фиксированная распиновка

Не менять GPIO без отдельного явного согласования.

```text
FR:
Coxa  GP2
Femur GP3
Tibia GP4

MR:
Coxa  GP5
Femur GP6
Tibia GP7

RR:
Coxa  GP8
Femur GP9
Tibia GP10

RL:
Coxa  GP11
Femur GP12
Tibia GP13

ML:
Coxa  GP14
Femur GP15
Tibia GP26

FL:
Coxa  GP27
Femur GP28
Tibia GP29
```

Дополнительно:

```text
UART0 TX: GP0
UART0 RX: GP1

GP16 не использовать:
он занят встроенным WS2812 на Waveshare RP2040-Zero.
```

UART работает с уровнями 3,3 В TTL.

Скорость UART по умолчанию:

`115200 baud, 8N1`

## Управление сервами через PIO

Использовать две PIO state machine:

```text
PIO0, state machine 0:
GP2–GP15, 14 каналов.

PIO0, state machine 1:
GP26–GP29, 4 канала.
```

Допускается использовать другой PIO-блок, только если это технически необходимо, но количество state machine должно остаться равным двум.

GPIO внутри каждой группы последовательны. Реализовать две версии PIO-программы или общий механизм с разной шириной выходной группы:

* 14 GPIO;
* 4 GPIO.

Требования к сигналу:

```text
Период кадра: 20 000 мкс.
Частота обновления: 50 Гц.
Длительность импульса каждого канала задаётся независимо.
Рабочая точность: не хуже 1 мкс.
```

Не формировать сигналы серв программными задержками в основном цикле.

Нельзя использовать:

* `sleep_ms()` или `sleep_us()` для формирования PWM;
* блокирующий цикл на время всего кадра;
* последовательную отправку импульсов из основного потока;
* аппаратный PWM для всех 18 каналов.

PIO должен получать предварительно рассчитанный список событий изменения выходной маски.

Рекомендуемая реализация:

1. Для каждого 20-миллисекундного кадра построить список событий:

   * время события в микросекундах;
   * новая битовая маска GPIO.
2. Отсортировать события по времени.
3. Передавать события в PIO через DMA.
4. Использовать двойную буферизацию:

   * один буфер воспроизводится PIO;
   * второй подготавливается CPU;
   * переключение происходит только на границе кадра.
5. Изменение целевых импульсов не должно повреждать текущий кадр.
6. При отключении выходов все сигнальные GPIO должны переходить в логический ноль.

Можно выбрать другую корректную реализацию PIO, если она:

* использует только две state machine;
* поддерживает 18 независимых импульсов;
* не блокирует основной код;
* не создаёт дрожание импульсов;
* позволяет разнести ноги по фазе;
* подробно объяснена в README.

## Фазовое распределение ног

Разнести начало импульсов шести ног внутри кадра 20 мс, чтобы три сервы одной ноги начинали импульс одновременно, а разные ноги — в разные моменты.

Использовать конфигурируемые значения:

```cpp
FR:     0 мкс
MR:  3333 мкс
RR:  6667 мкс
RL: 10000 мкс
ML: 13333 мкс
FL: 16667 мкс
```

Последний импульс должен гарантированно завершаться до конца кадра.

Максимально допустимую длительность импульса учитывать при проверке расписания.

Фазовые смещения должны храниться в отдельной таблице конфигурации, а не быть разбросаны по коду.

## Модель сервопривода

Создать перечисления:

```cpp
enum class Leg {
    FR,
    MR,
    RR,
    RL,
    ML,
    FL
};

enum class Joint {
    Coxa,
    Femur,
    Tibia
};
```

Создать конфигурацию каждой из 18 серв:

```cpp
struct ServoConfig {
    Leg leg;
    Joint joint;
    uint8_t gpio;

    uint16_t center_us;
    uint16_t pulse_minus_45_us;
    uint16_t pulse_plus_45_us;

    float min_angle_deg;
    float max_angle_deg;

    bool enabled;
};
```

Допускается добавить служебные поля, но перечисленные поля обязательно сохранить.

Для всех серв:

```text
center_us = 1500
min_angle_deg = −45
max_angle_deg = +45
enabled = true
```

Пока индивидуальные калибровки всех 18 серв не получены, использовать временные тестовые значения:

```text
pulse_minus_45_us = 2000
center_us         = 1500
pulse_plus_45_us  = 1000
```

Пометить эти значения в коде и README как временные, а не как окончательную калибровку.

Не добавлять отдельный флаг инверсии. Направление определяется самими калибровочными значениями.

## Преобразование угла в импульс

Реализовать кусочно-линейное преобразование.

Для диапазона от −45° до 0° интерполировать между:

```text
−45° → pulse_minus_45_us
  0° → center_us
```

Для диапазона от 0° до +45° интерполировать между:

```text
  0° → center_us
+45° → pulse_plus_45_us
```

Алгоритм должен корректно работать как с возрастающими, так и с убывающими значениями импульсов.

Перед преобразованием ограничивать угол диапазоном:

```text
min_angle_deg ... max_angle_deg
```

Линейную экстраполяцию за пределы −45…+45° пока не разрешать.

После вычисления дополнительно проверять разумный абсолютный диапазон импульса:

```text
500...2500 мкс
```

При ошибочной конфигурации не отправлять опасный импульс. Использовать центр 1500 мкс либо отключать конкретный канал и выводить диагностическое сообщение.

## Начальная стойка

Создать отдельную структуру позы:

```cpp
struct LegPose {
    float coxa_deg;
    float femur_deg;
    float tibia_deg;
};

struct RobotPose {
    std::array<LegPose, 6> legs;
};
```

Создать две позы:

### CENTER_POSE

Для всех ног:

```text
Coxa  = 0°
Femur = 0°
Tibia = 0°
```

### STAND_POSE

Пока использовать консервативную тестовую стойку:

```text
Coxa  = 0°
Femur = −15°
Tibia = +20°
```

Одинаковые логические углы применяются ко всем шести ногам. Направление вращения каждой физической сервы впоследствии определяется индивидуальными калибровочными значениями.

Все значения стойки должны находиться в одном конфигурационном файле, чтобы их можно было изменить без редактирования драйвера PIO.

Не размножать числа `−15` и `+20` по исходникам.

## Безопасная последовательность запуска

Реализовать неблокирующий автомат состояний запуска:

```text
BOOT
↓
OUTPUTS_DISABLED
↓
CENTERING
↓
MOVING_TO_STAND
↓
HOLDING_STAND
```

Последовательность:

1. После сброса все GPIO серв находятся в логическом нуле.
2. Инициализировать UART, USB-диагностику, конфигурацию, PIO и DMA.
3. Подождать 1000 мс, не включая импульсы серв.
4. Установить текущую и целевую позу в `CENTER_POSE`.
5. Включить формирование импульсов 1500 мкс.
6. Удерживать центр 1000 мс.
7. Плавно переместить все суставы из центра в `STAND_POSE`.
8. Время перехода в стойку — 3000 мс.
9. После завершения постоянно удерживать `STAND_POSE`.

Все ожидания реализовать через проверку времени и конечный автомат.

Не использовать блокирующие задержки.

UART должен обрабатываться во всех состояниях.

Добавить константу:

```cpp
constexpr bool AUTO_STAND_ON_BOOT = true;
```

Если она равна `false`, после запуска прошивка должна оставаться в центре и ждать команды `STAND`.

## Плавное движение

Создать независимый от PIO слой движения.

Хранить:

```text
текущий угол;
целевой угол;
максимальную скорость;
состояние движения.
```

Обновлять текущие углы каждые 20 мс или чаще.

Не изменять угол скачком.

Скорость движения по умолчанию:

```text
30 градусов в секунду
```

Для автоматического перехода из центра в стойку допускается вычислять скорость так, чтобы движение завершилось приблизительно за 3 секунды.

PIO-драйвер должен работать только с длительностями импульсов и не должен знать о понятиях `Leg`, `Joint`, стойка или скорость движения.

## UART

Командный UART:

```text
UART0
TX GP0
RX GP1
115200 baud
8N1
```

Реализовать неблокирующий построчный парсер.

Поддержать:

```text
PING
STATUS
ALL CENTER
STAND
ENABLE ALL
DISABLE ALL
SERVO <leg> <joint> <angle>
LEG <leg> <coxa> <femur> <tibia>
CAL SHOW <leg> <joint>
CAL SET <leg> <joint> MINUS45 <pulse_us>
CAL SET <leg> <joint> PLUS45 <pulse_us>
CAL SAVE
CAL LOAD
CAL RESET
HELP
```

Команды должны быть регистронезависимыми.

Принимать окончания строки:

* CR;
* LF;
* CRLF.

Максимальная длина строки — 128 символов.

Не использовать динамическое выделение памяти для UART-парсера.

Примеры ответов:

```text
PING
OK PONG
```

```text
STAND
OK STAND
```

```text
SERVO FR COXA 10
OK SERVO FR COXA 10.00
```

При ошибке:

```text
ERR UNKNOWN_COMMAND
ERR INVALID_ARGUMENT
ERR INVALID_LEG
ERR INVALID_JOINT
ERR ANGLE_OUT_OF_RANGE
ERR PULSE_OUT_OF_RANGE
ERR CONFIG_INVALID
```

Команда `STATUS` должна показывать как минимум:

```text
состояние контроллера;
включены ли выходы;
текущую позу;
целевую позу;
наличие валидной конфигурации Flash;
версию конфигурации;
количество ошибок UART;
количество ошибок PIO/DMA;
номер текущего кадра;
```

Команда `DISABLE ALL` должна немедленно остановить импульсы и установить сигнальные GPIO в ноль.

Команда `ENABLE ALL` должна возобновить удержание текущей позы без промежуточного случайного движения.

## USB-диагностика

Разрешить USB CDC только как диагностический вывод для отладки.

Не использовать USB CDC вместо UART0 для основного протокола управления.

Не направлять Pico SDK stdio на аппаратный UART0, потому что UART0 используется собственным командным протоколом.

USB-диагностика должна выводить:

* версию прошивки;
* результат загрузки конфигурации;
* запуск PIO;
* запуск DMA;
* переходы автомата состояний;
* ошибки.

Отсутствие открытого USB Serial Monitor не должно блокировать запуск прошивки.

## Хранение конфигурации

Реализовать отдельный модуль хранения калибровки во Flash.

Структура сохранённых данных должна содержать:

```cpp
struct StoredConfigHeader {
    uint32_t magic;
    uint16_t version;
    uint16_t payload_size;
    uint32_t crc32;
};
```

Использовать:

* фиксированный `magic`;
* версию формата;
* размер полезной части;
* CRC32 полезной части.

Требования:

1. При запуске проверить magic, version, размер и CRC.
2. Если данные корректны — загрузить их.
3. Если данные некорректны — использовать встроенную конфигурацию.
4. Не сохранять Flash автоматически.
5. Сохранять только по команде `CAL SAVE`.
6. `CAL LOAD` повторно загружает сохранённую конфигурацию.
7. `CAL RESET` возвращает встроенные значения в RAM, но не записывает их во Flash до `CAL SAVE`.
8. Перед записью Flash безопасно остановить обновление конфигурации PIO.
9. После записи восстановить работу без случайного изменения позы.
10. Не писать во Flash при каждом изменении угла или каждой команде `CAL SET`.

Выделить отдельный сектор в конце Flash и проверить, что он не пересекается с прошивкой.

Добавить предупреждение или ошибку сборки, если размер прошивки приближается к зарезервированному сектору.

## Многопоточность

Не требуется использовать второе ядро RP2040 на первом этапе.

Основной цикл должен быть неблокирующим и выполнять:

```text
обработку UART;
обновление автомата запуска;
обновление текущих углов;
подготовку следующего PIO-кадра;
обработку ошибок;
диагностику.
```

DMA и PIO самостоятельно воспроизводят текущий кадр.

Не использовать busy-wait на 20 мс.

## Проверки времени компиляции

Добавить `static_assert` или эквивалентные проверки:

1. Ровно 18 серв.
2. В каждой ноге ровно три сустава.
3. GPIO не повторяются.
4. GP0, GP1 и GP16 не попали в список серв.

9. Размер сохранённой конфигурации помещается в выделенный Flash-сектор.

## Сборка

Использовать официальный Pico SDK.

Проект должен собирать:

```text
RP2040RobotController.elf
RP2040RobotController.uf2
```

В CMake подключить необходимые библиотеки:

```text
pico_stdlib
hardware_uart
hardware_pio
hardware_dma
hardware_flash
hardware_sync
```

PIO-заголовки генерировать через CMake.

Для совместимости с Waveshare RP2040-Zero можно использовать базовую конфигурацию RP2040/Pico, не задействуя GPIO встроенного светодиода.

Если Pico SDK отсутствует:

1. Не переключаться самовольно на Arduino.
2. Проверить стандартные пути и переменную `PICO_SDK_PATH`.
3. При наличии разрешения можно скачать официальный Pico SDK и его submodules.
4. Не добавлять весь Pico SDK внутрь данного репозитория.
5. Описать настройку в README.

### flash.ps1

Поддержать два варианта:


Скрипт должен:

* найти диск `RPI-RP2` автоматически либо использовать переданную букву;
* проверить наличие UF2;
* скопировать UF2;
* вывести понятную ошибку, если плата не находится.

Скрипт не должен удалять посторонние файлы.

Первый безопасный запуск описать так:

```text
1. Не подключать сразу все сервы.
```

## Критерии готовности

Работа считается выполненной, если:

1. Создан отдельный проект `RP2040RobotController`.
2. Код собирается без ошибок.
3. Создаётся UF2.
4. Распиновка строго соответствует заданной.
5. Используются две PIO state machine.
6. Все 18 импульсов независимы.
7. UART не блокируется движением.
8. После запуска выполняется центрирование.
9. Затем выполняется плавный переход в `STAND_POSE`.
10. После перехода стойка удерживается.
11. Команда `DISABLE ALL` опускает все сигналы в ноль.
12. В коде нет Arduino API.
13. В коде нет управления всеми сервами через hardware PWM.
14. Калибровка имеет встроенные значения, Flash-версию, magic и CRC.
15. README содержит полную инструкцию.

## Обязательная проверка результата

После реализации:

1. Собери проект.
2. Запусти доступные тесты.
3. Проверь карту GPIO поиском по всему проекту.
4. Проверь, что GP0 и GP1 используются только для UART.
5. Проверь, что GP16 не используется.
6. Проверь, что в `ServoTester` нет изменений.
7. Проверь `git diff`.
